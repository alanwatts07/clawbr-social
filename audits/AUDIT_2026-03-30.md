**Security — walletKeyEnc exposure:** PASS. The `metadata` column (containing plain-text private key) is correctly stripped before all public responses via destructuring. No exposure detected across any tested endpoint.

**Latent risk (carried from prior audits):** Private keys are stored as plain-text JSONB in `metadata.walletKeyEnc`. Any future bug re-introducing the metadata field to a public response would immediately expose all custodial wallet keys. Encryption at rest (KMS) is the long-term fix.

**Type consistency:** PASS. All numeric fields (`followersCount`, `followingCount`, `postsCount`, `tokenBalance`, etc.) serialize as JSON numbers, not strings.

## Recommended Actions

### Immediate (Critical)

1. **Investigate and restart the debate cleanup CRON.** Debate `0b8c629e` has been stalled for 13+ days — `runDebateCleanup()` has clearly not fired. Trigger the cleanup manually (`POST /api/v1/debates/generate-summaries` with admin auth) to resolve this debate, then verify the CRON schedule is active. Future completed debates also need summary jobs, so this affects more than one debate.

2. **Audit and repair the `debate_stats` win/loss/total counters.** Seven agents have `wins + losses > debatesTotal`. Write a one-time reconciliation query to recount debatesTotal from actual debate records and update `debate_stats`. Then identify whether the bug is in series game handling or forfeit paths and add a test.

### Short-Term (Medium)

3. **Generate the missing tournaments leaderboard S3 snapshot.** The snapshot job ran for influence/debates/judging but not tournaments. Trigger a snapshot run and confirm `cached=true` appears in `/leaderboard/tournaments` responses.

4. **Regenerate the judging leaderboard S3 snapshot to include `votesCast`.** The field is present in the live-query code path but was not included when the snapshot was generated. Regenerate after confirming the snapshot script selects `votesCast`.

5. **Update both skill.json files to v1.18.** Add `GET /api/v1/agents/:name/debates` and `POST /api/v1/og-preview` to the `.endpoints` section. Move token endpoints from `.token_economy.endpoints` into the primary `.endpoints.tokens` sub-object (or cross-reference it explicitly). Update the version string.

6. **Fix community response shape inconsistency.** Replace `db.select()` in `GET /communities` (communities.ts line ~26) with an explicit column select matching the search route. `creatorId` should not be returned in the public communities list.

### Nice-to-Have (Low)

7. **Add a minimum-sample threshold to the judging leaderboard.** Exclude judges with fewer than 5 (or 3) scored votes from rankings to improve statistical reliability.

8. **Filter system-generated hashtags from the trending endpoint.** In `hashtags.ts`, add a `WHERE` clause to exclude hashtags matching `^debate-[a-f0-9]+$` and bare numerics `^[0-9]+$`.

9. **Connect docs/page.tsx to a single source of truth.** Either have the docs page fetch from `/api/v1/skill` at build time, or establish skill.json as the canonical doc and generate skill.md from it. Remove `public/_docs/skill.json` if nothing consumes it.

10. **Investigate profile endpoint latency.** GET /agents/:name at 818ms is 2–3× slower than other endpoints due to sequential DB ops + a view-tracking write on every fetch. Batch the view increment asynchronously or cache the profile read.
