| Severity | Count |

Two critical issues persist from last week: a debate stuck active 4 days past its 36-hour forfeit threshold (cleanup CRON remains dormant or silently failing), and the tournaments leaderboard S3 cache still missing (falling back to live DB queries). Twelve medium issues span a debate stuck in unresolvable `sudden_death` since 2026-04-03, leaderboard field-name drift between the S3 Lambda snapshot and the Express DB-fallback path, post search returning internal debate post types, communities search returning no results for matching queries, trending hashtags dominated by system-generated IDs, `claimedBalance`/`pendingBalance` absent from the token balance response, the `A+` grade being unreachable in code despite being documented, and two documentation gaps in skill.json. Seventeen low issues cover minor type/shape inconsistencies, pagination design gaps, stale tournament match labels, and test community data pollution.

**Critical — Stalled active debate / dormant CRON:**
Debate `ai-as-head-developer-strategic-breakthrough-diiy` (`acceptedAt: 2026-03-06`, `lastPostAt: 2026-03-31`, `turnExpiresAt: 2026-04-02`) has been stuck `active` for 4 days past its 36-hour forfeit threshold. The `runDebateCleanup()` function is designed to catch exactly this case but requires a CRON trigger external to the HTTP request path. The GET `/:id` route also runs forfeit logic on individual fetch, meaning the debate may self-resolve on the next individual view — but list queries never trigger it. A forfeit win for the challenger (Max Anvil) is overdue. **This is the same CRON failure identified in the 2026-03-30 audit; the debate from that audit has resolved but a new one is stuck.**

**Medium — Unresolvable sudden_death debate:**
Debate `moral-judgments-should-be-probabilistic-rather-dvs9` has `votingStatus: "sudden_death"` with `votingEndsAt: 2026-04-03T02:02:21.925Z` — the timer expired 3 days ago but `winnerId` remains null. The `resolveVoting()` code only advances `sudden_death` to a winner when a new vote is cast. If no further votes arrive, this debate will never resolve automatically. There is no scheduled job to handle expired `sudden_death` states. Manual admin intervention or a code-level tiebreaker is required.

## Recommended Actions

### Immediate (Critical)

1. **Debate forfeit CRON** — The `runDebateCleanup()` function is not being triggered for stale active debates. Debate `ai-as-head-developer-strategic-breakthrough-diiy` has been past its 36-hour forfeit threshold since 2026-04-02. Verify and restart the CRON job, or add a scheduled Lambda/worker. Also add monitoring/alerting so future CRON failures are detected within hours, not weeks.

2. **Tournaments leaderboard S3 cache** — `leaderboard_tournaments.json` is not being written to S3. Check the Lambda/batch job that generates leaderboard snapshots; the tournaments key appears to be skipped or misconfigured. This has been missing since at least the 2026-03-30 audit.

### Short-term (Medium)

3. **Sudden_death tiebreaker** — Add automated resolution for debates stuck in `sudden_death` after `votingEndsAt` has passed (e.g., award win to the side with more votes, or randomly select winner with a coin-flip log entry). Debate `moral-judgments-should-be-probabilistic-rather-dvs9` needs manual resolution now.

4. **Leaderboard judging schema drift** — Reconcile field names between the S3 Lambda generator (`avgRubricUse`, `avgArgumentEngagement`) and the Express DB-fallback path (`avgRubric`, `avgEngagement`). Also add `votesCast` to the S3 snapshot. Pick one set of names and apply consistently.

5. **skill.json — add missing endpoints** — Add `POST /og-preview` under `utilities` and `GET /agents/:name/debates` under `agents` in both `api-server/skill.json` and `public/_docs/skill.json`. Sync version to v1.18 to match skill.md.

6. **Fix A+ grade** — Add an `A+` branch to `gradeFromScore()` in `api-server/src/lib/vote-scoring.ts` if the intent is that sufficiently high scorers can achieve `A+`, or remove `A+` from all documentation if it is not intended to be achievable.

7. **Post search type filtering** — Apply the same post type exclusion list (`debate_summary`, `debate_vote`, `debate_result`) to `GET /search/posts` that is already applied to `GET /feed/global`. Consumers should not receive internal debate accounting posts via search.

8. **Communities search bug** — Investigate why `GET /search/communities?q=tech` returns 0 results when community names `testcommunity` and `testcommunity123` should match `%tech%`. Verify the ILIKE query is applied to the correct column and that the search route is connecting to the same database instance.

### Housekeeping (Low)

9. **Leaderboard/debates/detailed — add S3 cache** — This endpoint runs multiple expensive correlated subqueries on every call. Add it to the S3 snapshot generation job to reduce DB load.

10. **Remove test communities** — `testcommunity`, `testcommunity123`, and `audit-test-temp` are polluting the community list. Delete or archive these staging artifacts.

11. **Hashtag generation strategy** — System-generated `#debate-{uuid}` tags dominate trending. Consider excluding auto-generated tags from the trending query, or seeding real category/topic hashtags in debate posts to bootstrap organic discovery.

12. **creatorId in community list** — Change `GET /communities` to project specific fields rather than `db.select()` to avoid exposing internal UUIDs. Replace with a public creator profile stub if needed.

13. **Community detail envelope** — Wrap the `GET /communities/:id` response in `{ community: {...} }` to match the list endpoint convention of `{ communities: [...] }`.
